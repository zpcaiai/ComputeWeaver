# B01 — Platform Foundation, Monorepo and Reproducible Build

## 1. Mission

Create the executable repository foundation, development environment, coding standards, CI gates and evidence conventions used by every later batch.

## 2. Completion truth rule

Codex MUST NOT mark this batch `COMPLETE` because files were created or because code appears plausible. Completion requires all of the following:

1. Production implementation exists at the declared repository paths.
2. All required tests execute and pass.
3. Evidence artifacts are generated by the actual commands and reference the current commit.
4. No required interface is a stub, mock-only endpoint or unconditional success path.
5. The batch-specific Definition of Done and handoff contract are satisfied.

Allowed statuses are:

```text
NOT_STARTED
IMPLEMENTING
BLOCKED
EVIDENCE_PENDING
COMPLETE
```

## 3. Dependencies

`None`

Codex must verify dependency evidence before changing this batch to `IMPLEMENTING`. When a dependency interface is unavailable, create a typed temporary adapter behind the declared contract and keep the batch `BLOCKED` or `EVIDENCE_PENDING`; do not silently invent incompatible APIs.

## 4. Inputs

- Approved overall system design and bounded MVP scope.
- Target stack decision: Python 3.12/FastAPI/Pyomo or OR-Tools, Vue 3/TypeScript, PostgreSQL, object storage and OpenTelemetry.
- Supported environments: local Docker Compose first; Kubernetes-ready deployment contracts.
- Repository naming, licensing and organization conventions.

## 5. Scope and required code modules

- `pyproject.toml`, lockfile and Python workspace packages.
- `package.json`, package manager lockfile and Vue workspace.
- `apps/api`, `apps/web`, `apps/worker`, `apps/simulator` executable shells.
- `packages/domain`, `packages/contracts`, `packages/observability`, `packages/testing`.
- `deploy/compose`, `deploy/kubernetes`, `config`, `scripts`, `evidence`.
- CI workflows for format, lint, type-check, unit tests, security scan and build.
- Developer commands: bootstrap, lint, test, run, seed, validate and clean.

## 6. Required interfaces

- `GET /health/live`, `GET /health/ready`, `GET /version`.
- CLI: `make bootstrap`, `make verify`, `make dev`, `make evidence`.
- Configuration contract: environment variables with generated reference documentation.
- Standard service result, error envelope, correlation ID and trace context.

All write interfaces must specify authentication, authorization, tenant/site scope, idempotency behavior, validation errors, audit event and rollback/compensation behavior where applicable.

## 7. Implementation workflow

1. Inspect the repository and dependency evidence; record the exact commit.
2. Produce or update an implementation plan mapping every required module to concrete files.
3. Implement domain models and pure logic before transport and UI code.
4. Implement APIs/events/adapters using B02 contracts.
5. Add migrations, seed fixtures and configuration documentation.
6. Add tests before marking interfaces complete.
7. Run the batch verification commands from a clean state.
8. Generate the evidence pack automatically.
9. Review open TODO, FIXME, skipped tests and mock-only paths.
10. Update the batch manifest and handoff notes.

## 8. Required tests

- Fresh checkout bootstrap on a clean environment.
- API and web smoke tests under Docker Compose.
- Static typing, formatting and linting fail the build on violations.
- Dependency lock and reproducible build hash verification.
- Container non-root user and read-only filesystem smoke test.
- CI negative test proving a deliberately broken test blocks merge.

Minimum test classes:

```text
unit
property/algorithm
API or event contract
integration
negative/failure
security/authorization where relevant
scenario or regression
```

Skipped tests require an explicit waiver in `evidence/{b['id']}/waivers.json`; a waiver cannot cover a mandatory safety gate.

## 9. Required evidence

- `evidence/B01/build.log` and exact commands executed.
- `evidence/B01/test-results.xml` and coverage report.
- `evidence/B01/container-images.json` with immutable digests.
- `evidence/B01/sbom.*` and dependency vulnerability report.
- `evidence/B01/reproducibility.json` with two clean-build hashes.

Every evidence file must include or be accompanied by:

```json
{{
  "batch": "{b['id']}",
  "git_commit": "<sha>",
  "generated_at": "<UTC timestamp>",
  "command": "<exact command>",
  "result": "PASS|FAIL",
  "tool_versions": {{}}
}}
```

Screenshots alone are not proof of backend correctness.

## 10. Quality and safety gates

- No secrets, production credentials or real device write targets in fixtures.
- No silent fallback that changes a hard constraint into a soft preference.
- No LLM-generated value may bypass typed validation or the mathematical/safety layer.
- All externally visible errors use the shared error contract.
- State-changing operations are auditable.
- Data lineage and version provenance are preserved.
- New dependencies are locked, scanned and documented.
- Public interfaces receive contract tests.
- Failed mandatory gates block completion.

## 11. Definition of Done

- A clean checkout starts the API, web shell, worker and simulator with one documented command.
- All CI gates execute real commands; no placeholder success scripts exist.
- Build and test evidence is generated automatically and references the Git commit.
- No batch may introduce an alternative build convention without an architecture decision record.
- `python validate_package.py` and repository verification both pass.
